## 运行命令

### Oracle behavior-token clean strict

原因：MGNM 最强结果依赖行为 token；`--neg-prefix auto` 从 `expected_neg_behavior` 映射 `[SUPPRESS]` / `[SELECT]` / `[PRESERVE]`，因此只能标注为 oracle token，不是自动路由。

```bash
python scripts/evaluate_models.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output outputs/eval_clean_strict_oracle_token.json \
  --cache-dir outputs/score_cache_clean_strict_oracle \
  --model-names qwen2_5_7b \
  --neg-prefix auto
```

### No-token / empty-prefix clean strict

原因：no-token 是行为 token ablation，需要和 oracle token 分开报告；默认 `--neg-prefix ""` 不注入任何行为 token。

```bash
python scripts/evaluate_models.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output outputs/eval_clean_strict_no_token.json \
  --cache-dir outputs/score_cache_clean_strict_no_token \
  --model-names qwen2_5_7b
```

### Router prediction downstream

原因：`scripts/eval_with_router.py` 使用外部 `record_id -> token` JSON，适合评测 LLM router、supervised router、rule/hybrid router 的下游 NegFlipAcc / ScopeCtrl / NegRank。

```bash
python scripts/eval_with_router.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --predictions outputs/router_recommended_strict_predictions.json \
  --output outputs/eval_router_recommended_strict.json \
  --cache-dir outputs/score_cache_router_recommended \
  --model-names qwen2_5_7b
```

### Two-stage supervised router

原因：two-stage router 先分 preserve vs non-preserve，再分 suppress vs select，用于修复 preserve 被吸进 SELECT 的主要错误模式。

```bash
python scripts/supervised_router_twostage.py \
  --train data/processed/splits/router_calibration/train_fit_clean_strict.jsonl \
  --calibration data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  --test data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output-prefix outputs/supervised_router_twostage
```

### Text-derived suppression guard

原因：该 guard 只从 prompt 文本规则识别一批 factual suppress-only 模式，比 metadata guard 更接近纯文本路由，但覆盖范围有限。

```bash
python scripts/supervised_router_twostage.py \
  --train data/processed/splits/router_calibration/train_fit_clean_strict.jsonl \
  --calibration data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  --test data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output-prefix outputs/supervised_router_twostage_text_guard \
  --text-suppression-guard
```

已有 hybrid 入口也支持 text-derived guard + empty SELECT：

```bash
python scripts/hybrid_router_candidate.py \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --llm-predictions outputs/llm_router_candidate_predictions.json \
  --policy text_suppression_guard_empty_select \
  --output outputs/router_text_guard_empty_select_predictions.json
```

### Metadata-assisted suppression guard

原因：`--force-suppression-only` 读取 `semantic_mode=suppression_only`，可修复 WikiFact suppress-only 域外失败，但依赖结构化元数据，论文中必须写成 metadata-assisted / structure-assisted routing。

```bash
python scripts/supervised_router_twostage.py \
  --train data/processed/splits/router_calibration/train_fit_clean_strict.jsonl \
  --calibration data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  --test data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output-prefix outputs/supervised_router_twostage_metadata_guard \
  --force-suppression-only
```

### Recommended router aggregation

原因：现有一键脚本串联 hybrid prediction、downstream eval 和 summary，适合复现当前 recommended router 口径；默认复用已有 eval 输出，若要强制重跑需设置 `REUSE_EXISTING=0`。

```bash
REUSE_EXISTING=0 bash scripts/run_recommended_router_eval.sh \
  data/processed/validated_largetest_v2_clean_strict.jsonl \
  data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  outputs/llm_router_candidate_predictions.json \
  outputs/llm_router_candidate_calibration_clean_strict_predictions.json \
  outputs/router_recommended_strict_predictions.json \
  outputs/router_recommended_calibration_predictions.json \
  outputs/eval_router_recommended_strict.json \
  outputs/eval_router_recommended_calibration.json \
  outputs/router_recommended_summary.json
```

## 关键结果

- 本轮没有新增实验数字，只固定脚本入口和口径命名。
- Oracle token：`evaluate_models.py --neg-prefix auto`，依赖 `expected_neg_behavior` 标签。
- No-token：`evaluate_models.py` 默认空 prefix。
- Router downstream：`eval_with_router.py --predictions <json>`。
- Text-derived guard：`supervised_router_twostage.py --text-suppression-guard` 或 `hybrid_router_candidate.py --policy text_suppression_guard_empty_select`。
- Metadata guard：`supervised_router_twostage.py --force-suppression-only`，依赖 `semantic_mode`。

## 风险和下一步

- `--neg-prefix auto` 使用测试标签，不能称为自动路由。
- `--force-suppression-only` 是 metadata-assisted guard，不能包装成 pure-text router。
- `eval_with_router.py` 当前按 `predictions.get(record.id, "")` 处理缺失预测；正式实验应保证预测 JSON 覆盖全部输入记录，避免把漏预测样本隐式变成 no-token。
- `--use-multi-answer-negatives` 会改变 select 样本的 `neg_correct`，并影响 FlipAcc；clean strict 主结果应默认 hard single-gold，multi-answer 结果单独报告。
- 下一步可在有数据/模型的环境运行 recommended router 命令，并同时报告 router classification accuracy 与 downstream NegFlipAcc / ScopeCtrl / NegRank。
