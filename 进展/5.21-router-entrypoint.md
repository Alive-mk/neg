# 2026-05-21 Router 标准入口补齐

## 今日目标

原因：AGENTS 的最终可复现产物清单要求 `scripts/eval_router.py`，而仓库当前只有底层 downstream 入口 `scripts/eval_with_router.py`。Router 预测可能来自 oracle token、no-token、LLM router、supervised router、metadata guard 或 text-derived guard；本轮只补统一 downstream 评测入口，不生成新预测、不默认选择某个 router policy，避免把不同 router 口径混用。

## 修改文件

- `scripts/eval_router.py`
- `进展/5.21-router-entrypoint.md`

## 运行命令

```bash
python scripts/eval_router.py --help
python scripts/eval_with_router.py --help
python -m py_compile scripts/eval_router.py scripts/eval_with_router.py

printf '{"models":[{"name":"generator","mode":"chat_json"}]}\n' > /tmp/neg_router_models.json
: > /tmp/neg_router_empty.jsonl
printf '{}\n' > /tmp/neg_router_predictions.json
rm -f /tmp/neg_router_eval.json
python scripts/eval_router.py \
  --models /tmp/neg_router_models.json \
  --input /tmp/neg_router_empty.jsonl \
  --predictions /tmp/neg_router_predictions.json \
  --output /tmp/neg_router_eval.json \
  --cache-dir /tmp/neg_router_cache
cat /tmp/neg_router_eval.json
```

## 关键结果

- `scripts/eval_router.py` 是薄 wrapper，复用 `scripts/eval_with_router.py` 的评测逻辑。
- 默认输入：`data/processed/validated_largetest_v2_clean_strict.jsonl`。
- 默认输出：`outputs/eval_router.json`。
- 默认缓存：`outputs/score_cache_router`。
- `--predictions` 必须显式提供，避免把 LLM / supervised / metadata guard / text-derived guard 的预测文件混成同一口径。
- 默认不启用 `--use-multi-answer-negatives`，因此 downstream `NegRankAcc` 仍是 hard single-gold；multi-answer 只能作为显式诊断。
- 空输入 smoke test 输出 `{}`，验证 wrapper 能转发参数且不加载模型。

标准运行示例：

```bash
python scripts/eval_router.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --predictions outputs/router_recommended_strict_predictions.json \
  --output outputs/eval_router_recommended_clean_strict.json \
  --cache-dir outputs/score_cache_router_recommended \
  --model-names qwen2_5_7b
```

## 是否进入论文

该改动不产生新实验数字，不能单独进入论文主表。它可进入 reproducibility appendix 或 release artifact 命令清单，用于固定 router downstream 评测入口。

## 风险和下一步

- 本轮没有运行真实 router downstream 评测，因为需要本地 clean strict 数据、router predictions、模型权重和 GPU。
- `eval_router.py` 只评估已有 token predictions 的下游效果；router classification accuracy、suppress recall、preserve recall 和 select accuracy 仍需配合 `summarize_recommended_router.py` 或对应 router 脚本报告。
- 如果论文声称 text-derived guard，必须使用不依赖 `semantic_mode` / `scope_type` 的预测文件，并在结果名中显式标注 `text-derived`。
