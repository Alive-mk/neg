# 2026-05-20 BoolQ 入口梳理

## 今日目标

原因：P0 要求 BoolQ 结果区分 raw accuracy、standard PMI、scalar PMI、held-out calibration 和 training tradeoff。当前仓库已有多个 BoolQ 脚本，但入口分散；如果直接混用 `eval_boolq_pmi.py --alpha`、`boolq_alpha_calibration.py` 和 `eval_boolq_with_token.py` 的结果，容易把主表标准 PMI、调参诊断和 token 分布外诊断写成同一口径。

本轮只梳理现有脚本入口，不跑重模型，不生成 `data/`、`outputs/` 或 `model/` 产物。

## 运行命令

### 1. 数据准备

用途：从 Hugging Face BoolQ 生成两个本地评测文件：否定子集和 full validation。该命令会写入 `data/`，本轮未执行。

```bash
python scripts/prepare_boolq_negation.py
```

输出约定：

```text
data/boolq_negation.jsonl
data/boolq_full_val.jsonl
```

### 2. Raw BoolQ accuracy

用途：计算原始 yes/no log-probability ranking accuracy。full validation 才是通用 QA retention 主报告口径；negation subset 只是补充诊断。

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/eval_boolq_negation.py \
  --models-config configs/model_config_boolq.json \
  --input data/boolq_full_val.jsonl \
  --output outputs/eval_boolq_full_qwen.json \
  --cache-dir outputs/score_cache_boolq \
  --model-names qwen_base qwen_dpo qwen_nc_sft qwen_mgnm
```

```bash
CUDA_VISIBLE_DEVICES=4 python scripts/eval_boolq_negation.py \
  --models-config configs/model_config_boolq.json \
  --input data/boolq_full_val.jsonl \
  --output outputs/eval_boolq_full_llama.json \
  --cache-dir outputs/score_cache_boolq \
  --model-names llama_base llama_dpo llama_nc_sft llama_mgnm
```

### 3. Standard PMI calibration

用途：标准 PMI 使用 `alpha=1.0`，即 `log p(answer | prompt) - log p(answer | null_prompt)`。这是主表可报告的 PMI 校准口径；不要把 full-validation 最优 alpha 当成主表值。

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/eval_boolq_pmi.py \
  --models-config configs/model_config_boolq.json \
  --input data/boolq_full_val.jsonl \
  --output outputs/eval_boolq_full_pmi_qwen.json \
  --cache-dir outputs/score_cache_boolq \
  --model-names qwen_base qwen_dpo qwen_nc_sft qwen_mgnm \
  --alpha 1.0
```

```bash
CUDA_VISIBLE_DEVICES=4 python scripts/eval_boolq_pmi.py \
  --models-config configs/model_config_boolq.json \
  --input data/boolq_full_val.jsonl \
  --output outputs/eval_boolq_full_pmi_llama.json \
  --cache-dir outputs/score_cache_boolq \
  --model-names llama_base llama_dpo llama_nc_sft llama_mgnm \
  --alpha 1.0
```

### 4. Scalar PMI / held-out calibration diagnostic

用途：离线读取 raw eval 的 per-record scores 和 standard PMI 输出中的 null prior，搜索 scalar `alpha`。该脚本适合做 calibration/tradeoff 诊断；只有 held-out calibration split 上选择的 alpha 才能作为部署设置讨论。

```bash
python scripts/boolq_alpha_calibration.py \
  --raw-eval outputs/eval_boolq_full_llama.json \
  --pmi-eval outputs/eval_boolq_full_pmi_llama.json \
  --model llama_mgnm \
  --output outputs/boolq_alpha_calibration_llama_mgnm.json \
  --max-alpha 2.5 \
  --step 0.01 \
  --folds 5 \
  --seed 7 \
  --calibration-ratio 0.2 \
  --heldout-seeds 7,13,29,43,71
```

如需额外生成某个固定 alpha 的重评分 eval 文件，应明确标注为 diagnostic / tuned-alpha，不替代 standard PMI 主表：

```bash
python scripts/boolq_alpha_calibration.py \
  --raw-eval outputs/eval_boolq_full_llama.json \
  --pmi-eval outputs/eval_boolq_full_pmi_llama.json \
  --model llama_mgnm \
  --output outputs/boolq_alpha_calibration_llama_mgnm.json \
  --emit-rescored-output outputs/eval_boolq_full_pmi_alpha165_llama_mgnm.json \
  --rescore-alpha 1.65
```

### 5. Behavior-token BoolQ diagnostic

用途：测试 `[PRESERVE]` 等 behavior token 是否跨任务迁移。该入口是分布外 token 诊断，不是 BoolQ 主评测或 calibration 修复。

```bash
CUDA_VISIBLE_DEVICES=3 python scripts/eval_boolq_with_token.py \
  --models-config configs/model_config_boolq.json \
  --input data/boolq_full_val.jsonl \
  --output outputs/eval_boolq_full_with_preserve_qwen.json \
  --cache-dir outputs/score_cache_boolq \
  --model-names qwen_mgnm \
  --prefix "[PRESERVE]"
```

### 6. 一键脚本和表格打印

用途：`run_boolq_eval.sh` 串起数据准备、raw eval、standard PMI 和 summary 打印。它默认并行跑 Qwen/Llama 全模型组，属于重评测入口；本轮只做语法验证。

```bash
bash scripts/run_boolq_eval.sh
```

已有输出后，可打印 raw/PMI 汇总表和 null-prompt No-bias 诊断：

```bash
python scripts/print_boolq_results.py
```

## 关键结果

- `scripts/eval_boolq_negation.py` 是 raw accuracy 入口；full validation 输出应命名为 `outputs/eval_boolq_full_<group>.json`。
- `scripts/eval_boolq_pmi.py --alpha 1.0` 是 standard PMI 主报告口径；输出包含 `summary_raw`、`summary_pmi`、`prior` 和 `alpha`。
- `scripts/boolq_alpha_calibration.py` 是 offline scalar PMI 诊断；它用已有 raw per-record scores 和 PMI prior 做 cross-validation / held-out calibration，不重新跑模型。
- `scripts/eval_boolq_with_token.py` 是 behavior-token task specificity 诊断；结果不能写成 BoolQ 主表改进。
- `scripts/run_boolq_eval.sh` 是重评测流水线，会写入 `data/` 和 `outputs/`，适合完整复现时执行。

## 风险和下一步

- 本轮没有执行 `prepare_boolq_negation.py` 或真实 BoolQ 模型评测，因为它会下载数据、写入 `data/`，并需要本地模型权重/GPU。
- `configs/model_config_boolq.json` 当前包含本地绝对模型路径和 `outputs/.../adapter` 路径；论文复现材料需要另外说明环境映射或提供 example config，避免把本机路径当成通用路径。
- 若某 checkpoint 恢复 BoolQ raw 但 E4/WikiFact 下降，应按 AGENTS 规范写成 `training tradeoff`，不能作为主模型整体改进。
