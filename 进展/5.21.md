## 今日目标

补齐 clean strict 主评测的标准脚本入口，避免继续直接记忆 `evaluate_models.py` 参数组合。

## 修改文件

- `scripts/eval_clean_strict.py`：新增薄 wrapper，转发到 `scripts/evaluate_models.py`。

## 运行命令

```bash
python scripts/eval_clean_strict.py --help
python -m py_compile scripts/eval_clean_strict.py scripts/evaluate_models.py
```

## 关键结果

- 默认 input 为 `data/processed/validated_largetest_v2_clean_strict.jsonl`。
- 默认 output 为 `outputs/eval_clean_strict.json`。
- 默认 cache 为 `outputs/score_cache_clean_strict`。
- 默认不传 `--use-multi-answer-negatives`，因此 `select_gold_neg` 的 `neg_correct` 和 `FlipAcc` 保持 hard single-gold 口径。
- `MultiAnswerNegRankAcc` 仍由底层 `aggregate_results` 同时报告，作为 SELECT 歧义诊断；显式传 `--use-multi-answer-negatives` 才会改变 select correctness / FlipAcc 口径。

## 风险和下一步

- 风险：该 wrapper 只规范入口，不验证本地 clean strict 数据文件是否存在，也不跑重模型评测。
- 下一步：用小 fixture 或已有输出验证 `reaggregate_on_clean_e4.py` 的 Hard NegRank 与 MultiAnswerNegRank 口径，继续降低 SELECT 指标漂移风险。
