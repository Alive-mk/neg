## 今日目标

补齐 clean strict 主评测的标准脚本入口，使后续训练记录可直接引用 `scripts/eval_clean_strict.py`，同时复用现有 `scripts/evaluate_models.py`，避免重复实现评分逻辑。

## 修改文件

- `scripts/eval_clean_strict.py`：新增薄 wrapper，直接调用 `evaluate_models.main()`。
- `进展/5.21.md`：记录本轮可复现性补强。

## 运行命令

```bash
python -m py_compile scripts/eval_clean_strict.py scripts/evaluate_models.py
python scripts/eval_clean_strict.py --help
```

## 关键结果

- `eval_clean_strict.py` 不实现新的评分函数，只复用 `evaluate_models.py`。
- 默认不传 `--use-multi-answer-negatives`，因此 `select_gold_neg` 的 `neg_correct` 仍使用 hard single-gold `NegRankAcc`。
- `MultiAnswerNegRankAcc` 仍由底层聚合输出保留，只有显式传入 `--use-multi-answer-negatives` 时才改变 `neg_correct` 的选择口径。

## 是否进入论文

不作为实验结果进入论文主表；可作为 reproducibility appendix 的 clean strict 评测入口。

- 风险：该 wrapper 只是标准入口，不验证具体模型输出；真实主表仍需在固定 split、固定 model config 和固定 cache/output 路径下重跑或引用已有结果。
