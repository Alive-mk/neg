## 今日目标

补齐 P0 clean strict 主评测的标准脚本入口，提供 `scripts/eval_clean_strict.py` 薄 wrapper，便于后续主表复现。

## 修改文件

- 新增 `scripts/eval_clean_strict.py`：复用 `scripts/evaluate_models.py`，默认读取 `data/processed/validated_largetest_v2_clean_strict.jsonl`，默认输出 `outputs/eval_clean_strict.json`。

## 运行命令

```bash
python - <<'PY'
from scripts.eval_clean_strict import DEFAULT_CACHE_DIR, DEFAULT_INPUT, DEFAULT_OUTPUT, build_parser

args = build_parser().parse_args(['--models', '/tmp/eval_clean_strict_empty_models.json'])
assert args.input == DEFAULT_INPUT
assert args.output == DEFAULT_OUTPUT
assert args.cache_dir == DEFAULT_CACHE_DIR
assert args.use_multi_answer_negatives is False
print('clean_strict_defaults_ok')
PY

python scripts/eval_clean_strict.py --help

python scripts/eval_clean_strict.py \
  --models /tmp/eval_clean_strict_empty_models.json \
  --input /tmp/eval_clean_strict_fixture.jsonl \
  --output /tmp/eval_clean_strict_result.json \
  --cache-dir /tmp/eval_clean_strict_cache

python -m py_compile scripts/eval_clean_strict.py scripts/evaluate_models.py
```

## 关键结果

- wrapper 可正常转发到 `evaluate_models.py` 并写出 JSON。
- 默认不启用 `--use-multi-answer-negatives`，因此 clean strict 默认仍是 hard single-gold NegRank 口径。
- 未运行重模型训练，未生成或提交 `data/`、`outputs/`、`model/` 产物。

## 是否进入论文

不直接进入论文结果表；作为 clean strict 主评测的可复现入口进入 release / reproducibility appendix 更合适。

## 风险和下一步

- 风险：该 wrapper 只规范入口，不验证真实 checkpoint 的数值结果；真实评测仍依赖 `configs/model_config*.json` 和本地模型/缓存可用性。
- 下一步：可继续补 `eval_wikifact.py`、`eval_boolq.py`、`eval_router.py` 等同类标准入口，或补 clean strict reaggregation fixture。
