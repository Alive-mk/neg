# 2026-05-21 进展日报

## 今日目标

补齐 P0 clean strict 主评测的标准脚本入口：新增 `scripts/eval_clean_strict.py` 薄 wrapper，复用 `scripts/evaluate_models.py`，默认保持 hard single-gold NegRank，不改变指标口径。

## 修改文件

- `scripts/eval_clean_strict.py`：新增 clean strict 评测入口，默认读取 `data/processed/validated_largetest_v2_clean_strict.jsonl`，默认输出 `outputs/eval_clean_strict.json`，默认 cache 为 `outputs/score_cache_clean_strict`。
- `进展/5.21.md`：记录本轮可复现入口补齐、验证命令和风险。

## 运行命令

```bash
python -m py_compile scripts/eval_clean_strict.py scripts/evaluate_models.py

tmpdir="$(mktemp -d)"
printf '{"models":[]}\n' > "$tmpdir/models.json"
: > "$tmpdir/empty.jsonl"
python scripts/eval_clean_strict.py \
  --models "$tmpdir/models.json" \
  --input "$tmpdir/empty.jsonl" \
  --output "$tmpdir/eval.json" \
  --cache-dir "$tmpdir/cache"
cat "$tmpdir/eval.json"
rm -rf "$tmpdir"
```

## 关键结果

- `eval_clean_strict.py` 只负责提供 clean strict 默认路径和标准入口名，核心 scoring / aggregation 仍由 `evaluate_models.py` 执行。
- 默认不传 `--use-multi-answer-negatives`，因此 SELECT 的 `NegRankAcc` 仍是 strict single-gold / hard NegRank；需要 soft multi-answer 时必须显式 opt in。
- 该改动不新增依赖，不写入 `data/`、`outputs/`、`model/`，验证仅使用 `/tmp` 空 fixture。
