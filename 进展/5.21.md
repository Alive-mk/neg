# 2026-05-21 进展日报

## 今日目标

补齐 clean strict 主评测的标准入口脚本，降低后续复现实验需要记忆底层脚本映射的风险。

## 修改文件

- 新增 `scripts/eval_clean_strict.py`：薄 wrapper，复用 `scripts/evaluate_models.py`，仅在调用方未传 `--input` 时默认使用 `data/processed/validated_largetest_v2_clean_strict.jsonl`。
- 小幅调整 `scripts/evaluate_models.py`：抽出 parser 构造函数，让 wrapper 能把 `--input` 显示为可选，同时保持原脚本默认要求 `--input` 的行为不变。

import sys
from pathlib import Path
sys.path.append(str(Path.cwd() / 'src'))

from neg_blindness.api import ModelConfig
from neg_blindness.schema import ExperimentRecord
import neg_blindness.evaluation as evaluation

record = ExperimentRecord(
    id='fixture-select-1',
    neg_type='noun',
    scope_type='in_scope',
    semantic_mode='exclusive_choice',
    expected_neg_behavior='select_gold_neg',
    domain='fixture',
    prompt_pos='Pick the positive answer:',
    prompt_neg='Pick a valid negative answer:',
    gold_pos=['positive'],
    gold_neg=['hard-gold'],
    forbidden_neg=['positive'],
    candidate_pool_neg=['soft-valid', 'distractor'],
    valid_negatives=['soft-valid'],
    distractors=['distractor'],
    template_id='fixture',
    family_id='fixture',
    entity_id='fixture',
)
config = ModelConfig(name='fixture', mode='choice')
original_score_candidates = evaluation.score_candidates

def fake_score_candidates(config, prompt, candidates, cache):
    winner = 'positive' if prompt == record.prompt_pos else 'soft-valid'
    return {candidate: (1.0 if candidate == winner else 0.0) for candidate in candidates}

try:
    evaluation.score_candidates = fake_score_candidates
    hard = evaluation.evaluate_record(record, config, use_multi_answer_negatives=False)
    multi = evaluation.evaluate_record(record, config, use_multi_answer_negatives=True)
finally:
    evaluation.score_candidates = original_score_candidates

assert hard['neg_best'] == 'soft-valid'
assert hard['neg_rank_correct'] is False
assert hard['multi_neg_rank_correct'] is True
assert hard['neg_correct'] is False
assert multi['neg_correct'] is True
print('hard_default_neg_correct=', hard['neg_correct'])
print('multi_flag_neg_correct=', multi['neg_correct'])

验证结果：

- `eval_clean_strict.py --help` 通过，`--input` 在 wrapper 中为可选参数。
- `evaluate_models.py --help` 通过，底层脚本仍要求显式传 `--input`。
- `py_compile` 通过。
- hard / multi-answer fixture 通过：默认 `hard_default_neg_correct=False`，显式 multi-answer 后 `multi_flag_neg_correct=True`。
- wrapper CLI smoke 通过：空模型配置输出 `{}`，说明入口可运行且不触发模型评测。

## 关键结果

- 默认评测口径保持 hard single-gold：wrapper 不自动启用 `--use-multi-answer-negatives`。
- Multi-answer SELECT 口径仍需调用方显式传入 `--use-multi-answer-negatives`，避免主评测默认指标漂移。
