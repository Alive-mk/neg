## 关键结果

- wrapper 默认输入为 `data/processed/validated_largetest_v2_clean_strict.jsonl`。
- wrapper 默认输出为 `outputs/eval_clean_strict.json`，默认 cache 为 `outputs/score_cache_clean_strict`。
- wrapper 只转发参数到 `scripts/evaluate_models.py`，不修改 `evaluate_record` 或 `aggregate_results`。
- 默认不传 `--use-multi-answer-negatives`，因此 SELECT 的 `neg_correct` / `FlipAcc` 默认仍使用 hard single-gold；`MultiAnswerNegRankAcc` 仍由底层聚合函数单独报告。
- 语法编译、help 输出、默认 dry-run 和 multi-answer opt-in dry-run 均通过；本轮未运行重模型评测。

## 风险和下一步

- 本轮只做 CLI wrapper 验证，没有实际加载模型或生成评测 JSON；需要后续在有 GPU/模型环境时运行完整命令。
- `--use-multi-answer-negatives` 会改变 `neg_correct` / `FlipAcc` 的 SELECT 计分口径；论文主表默认命令不应启用该选项，multi-answer 结果应单独报告。
- 下一步可继续补 `eval_wikifact.py`、`eval_boolq.py`、`eval_mmlu.py` 或轻量 fixture 来验证 hard / multi-answer reaggregation 口径。
