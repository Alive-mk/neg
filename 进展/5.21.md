## 今日目标

补齐 clean strict 主评测的标准入口，使 P0 clean strict 评测可以直接调用 `scripts/eval_clean_strict.py`，同时避免重复实现或改变 `evaluate_models.py` 的指标逻辑。

## 修改文件

- `scripts/eval_clean_strict.py`

## 运行命令

```bash
python scripts/eval_clean_strict.py --help
python -m py_compile scripts/eval_clean_strict.py scripts/evaluate_models.py
python - <<'PY'
import sys
import scripts.eval_clean_strict as m

seen = {}
def fake_main():
    seen["argv"] = sys.argv[:]

m.evaluate_models_main = fake_main
sys.argv = [
    "scripts/eval_clean_strict.py",
    "--models", "configs/model_config.json",
    "--output", "/tmp/eval.json",
]
m.main()
assert "--input" in seen["argv"]
assert "data/processed/validated_largetest_v2_clean_strict.jsonl" in seen["argv"]
assert "--use-multi-answer-negatives" not in seen["argv"]
PY
```

## 关键结果

- 新入口默认使用 `data/processed/validated_largetest_v2_clean_strict.jsonl`。
- 评分、聚合、cache、model selection 和 `--use-multi-answer-negatives` 行为全部复用 `scripts/evaluate_models.py`。
- 默认不传 `--use-multi-answer-negatives`，因此仍是 hard single-gold NegRank 口径。
- smoke test 确认 wrapper 会补默认 `--input`，且不会默认追加 `--use-multi-answer-negatives`。

## 是否进入论文

不作为实验结果进入论文；可作为 reproducibility appendix 中 clean strict 主评测命令入口。

## 风险和下一步

- 风险：该 wrapper 只稳定入口，不验证真实模型输出；真实主表仍需要在固定 model config、clean strict split 和 baseline 集合上运行。
- 下一步：补齐 WikiFact、BoolQ、MMLU 等 P0 入口时，也应保持薄 wrapper 或明确映射，不改变已有指标定义。
