## 关键结果

当前 clean strict 主评测入口映射如下：

| 计划入口 | 当前实现 | 说明 |
| --- | --- | --- |
| `scripts/eval_clean_strict.py` | 新增薄 wrapper | 默认输入 `data/processed/validated_largetest_v2_clean_strict.jsonl`，默认输出 `outputs/eval_clean_strict.json`。 |
| `scripts/evaluate_models.py` | 底层候选排名评测 | 继续负责读取模型配置、加载 E4 记录、逐样本打分、输出 `summary` + `per_record`。 |
| `scripts/reaggregate_on_clean_e4.py` | 已有结果重聚合 | 已有 per-record 输出时，可按 clean strict ID 子集重算指标，避免重复跑模型。 |

推荐 clean strict oracle-token 主评测命令：

```bash
python scripts/eval_clean_strict.py \
  --models configs/model_config.json \
  --output outputs/eval_<run_name>_clean_strict.json \
  --cache-dir outputs/score_cache_<run_name>_clean_strict \
  --model-names <model_name>
```

口径说明：

- `scripts/eval_clean_strict.py` 默认 `--neg-prefix auto`，即按 `expected_neg_behavior` 注入 `[SUPPRESS]`、`[SELECT]`、`[PRESERVE]`，对应 oracle behavior token 评测。
- 默认不启用 `--use-multi-answer-negatives`，因此 `NegRankAcc` 保持 hard single-gold 主表口径。
- `--use-multi-answer-negatives` 只用于 SELECT 多答案诊断；底层仍输出 `MultiAnswerNegRankAcc`，不替代 hard NegRank。
- 本次改动只抽出 `evaluate_models.run_evaluation(...)` 复用原有逻辑，没有改变 `evaluate_record`、`aggregate_results` 或任何 metric 定义。
