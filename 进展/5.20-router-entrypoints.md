# 2026-05-20 Router 入口梳理

## 今日目标

原因：P0 的 router 评测有四类容易混用的口径：oracle token、no token、router predictions、metadata/text-derived guard。若命令模板不分清，后续主表会把 `expected_neg_behavior` 注入、结构化元数据 guard 或空 SELECT 前缀混在一起，造成 prompt/protocol drift。

本轮只梳理现有脚本入口，不跑重模型，不生成 `data/`、`outputs/` 或 `model/` 产物。

## 修改文件

- 新增本进展日志：`进展/5.20-router-entrypoints.md`

## 运行命令

### 1. No-token candidate ranking

用途：同一 MGNM checkpoint 的无行为 token 对照；也适用于 base / SFT / DPO / NC-SFT 等 baseline。默认 hard single-gold NegRank；不要传 `--use-multi-answer-negatives`。

```bash
python scripts/evaluate_models.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output outputs/eval_clean_strict_no_token.json \
  --cache-dir outputs/score_cache_clean_strict_no_token \
  --model-names qwen2_5_7b_e4
```

### 2. Oracle-token candidate ranking

用途：MGNM oracle behavior-token 上限；`--neg-prefix auto` 会读取 `expected_neg_behavior` 并注入 `[SUPPRESS]` / `[SELECT]` / `[PRESERVE]`。这不是自动路由，不能用于普通 baseline。

```bash
python scripts/evaluate_models.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output outputs/eval_clean_strict_oracle_token.json \
  --cache-dir outputs/score_cache_clean_strict_oracle_token \
  --model-names qwen2_5_7b_e4 \
  --neg-prefix auto
```

### 3. Router predictions downstream eval

用途：给定 `record_id -> token` 的预测文件后，评估 routed downstream 指标。预测值为 `""` 时表示 no token，常用于 empty SELECT。默认 hard single-gold NegRank；multi-answer 只能作为单独诊断显式加 `--use-multi-answer-negatives`。

```bash
python scripts/eval_with_router.py \
  --models configs/model_config.json \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --predictions outputs/router_predictions.json \
  --output outputs/eval_router_clean_strict.json \
  --cache-dir outputs/score_cache_router_clean_strict \
  --model-names qwen2_5_7b_e4
```

### 4. Candidate-aware LLM router

用途：生成候选感知 LLM router 预测。脚本只给 LLM 正向 prompt、否定 prompt 和未标注候选池；不提供 `expected_neg_behavior` 或 gold candidate。运行需要 `NEG_OPENAI_API_KEY`，会调用外部 API。

```bash
python scripts/llm_router_candidate.py \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output outputs/llm_router_candidate_predictions.json \
  --resume
```

### 5. Recommended hybrid router

用途：用候选感知 LLM 预测叠加保守规则，默认 `recommended` 等价于 `narrow_preserve_empty_select`，即预测 SELECT 时使用空前缀。该入口不是 oracle；但依赖已有 LLM prediction 文件。

```bash
python scripts/hybrid_router_candidate.py \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --llm-predictions outputs/llm_router_candidate_predictions.json \
  --policy recommended \
  --output outputs/router_recommended_strict_predictions.json
```

### 6. Text-derived suppression guard

用途：用 prompt 文本规则识别一批 suppress-only 模板，再叠加 empty SELECT。这个入口不读取 `semantic_mode=suppression_only`，更适合写成 text-derived guard 诊断。

```bash
python scripts/hybrid_router_candidate.py \
  --input data/processed/validated_largetest_v2_clean_strict.jsonl \
  --llm-predictions outputs/llm_router_candidate_predictions.json \
  --policy text_suppression_guard_empty_select \
  --output outputs/router_text_suppression_guard_predictions.json
```

### 7. Two-stage supervised router

用途：训练 preserve-first 的 two-stage supervised router，并在 calibration split 选阈值。注意当前 `supervised_router_twostage.py` 的特征包含 `semantic_mode` 和 `scope_type`，因此应写成 structure-assisted / metadata-assisted router，而不是纯文本 router。

```bash
python scripts/supervised_router_twostage.py \
  --train data/processed/splits/router_calibration/train_fit_clean_strict.jsonl \
  --calibration data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  --test data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output-prefix outputs/supervised_router_twostage
```

### 8. Metadata suppression-only guard

用途：在 two-stage router 基础上，遇到 `semantic_mode=suppression_only` 时强制路由为 `[SUPPRESS]`。这是 metadata-assisted guard，不能伪装成纯文本路由。

```bash
python scripts/supervised_router_twostage.py \
  --train data/processed/splits/router_calibration/train_fit_clean_strict.jsonl \
  --calibration data/processed/splits/router_calibration/calibration_clean_strict.jsonl \
  --test data/processed/validated_largetest_v2_clean_strict.jsonl \
  --output-prefix outputs/supervised_router_twostage_metadata_guard \
  --force-suppression-only
```

## 关键结果

- `scripts/evaluate_models.py --neg-prefix auto` 是 oracle token 口径，只能用于 MGNM oracle 上限，不是自动 router。
- `scripts/evaluate_models.py` 省略 `--neg-prefix` 是 no-token 口径，可用于 baseline 和 MGNM no-token 对照。
- `scripts/eval_with_router.py` 是 routed downstream 统一评测入口；predictions 中的空字符串表示 no-token / empty SELECT。
- `scripts/hybrid_router_candidate.py --policy text_suppression_guard_empty_select` 是当前更接近 text-derived suppression guard 的入口。
- `scripts/supervised_router_twostage.py --force-suppression-only` 是 metadata guard；脚本本身还把 `semantic_mode` / `scope_type` 放入 supervised 特征，因此相关结果应写成 structure-assisted / metadata-assisted routing。

## 风险和下一步

- 本轮没有运行真实模型评测，因为当前任务限定为入口梳理，且 worktree 未包含本地 `data/`、模型权重或 GPU 评测资源。
- 若论文声称 text-derived guard，需要优先使用 `hybrid_router_candidate.py --policy text_suppression_guard_empty_select`，或新增一个不使用 `semantic_mode` / `scope_type` 的 supervised router 变体。
- 后续可补 `scripts/eval_router.py` 薄 wrapper，把 predictions 生成、downstream eval 和 summary 聚合串成标准入口，但应保持 oracle/no-token/router 三种口径显式分离。
