## 关键结果

- 新脚本支持两种输入：
  - `--split-input SPLIT=PATH`：检查现有 E4 train/dev/test JSONL。
  - `--input PATH`：检查带 `split` 字段的 E4v3 release JSONL。
- 默认把 `record_id`、exact `prompt_pair`、`holdout_group` 跨 split 重叠视为失败；故意泄漏 fixture 正确以非零退出并报告 `LEAK train_vs_test prompt_pair: 1`。
- `template_id`、`family_id`、`entity_id` 也会进入 report；若需要 unseen-template 或更严格 family/entity holdout，可用：

```bash
python scripts/check_leakage.py \
  --split-input train=data/processed/splits/train.jsonl \
  --split-input test=data/processed/splits/test.jsonl \
  --report outputs/leakage_report.json \
  --fail-on record_id,prompt_pair,template_id,family_id,entity_id,holdout_group
```

## 是否进入论文

不作为新实验结果进入论文主表；适合进入 reproducibility appendix 或 release checklist，作为固定 split 无泄漏检查命令。

## 风险和下一步

- 当前脚本只检查跨 split 重叠，不替代 `validate_dataset.py` 或 `validate_e4v3_schema.py` 的 schema / candidate label 检查。
- 默认不把 `template_id`、`family_id`、`entity_id` overlap 直接判失败，因为部分 seen-eval 或非 held-out split 可能允许这些字段重叠；正式 unseen-template 评测必须显式加到 `--fail-on`。
