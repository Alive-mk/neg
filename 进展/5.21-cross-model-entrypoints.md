## 关键结果

现有入口分工如下：

| 目标 | 现有入口 | 当前作用 |
| --- | --- | --- |
| Qwen / Llama 新 checkpoint E4 + WikiFact + MMLU | `scripts/eval_new_models.sh` | 等待指定 adapter 完成后，构造临时 config，分别跑 largetest、WikiFact 和 570-question MMLU diagnostic。 |
| Mistral MGNM E4 + WikiFact + MMLU | `scripts/eval_mistral_e4.sh` | 构造 Mistral adapter config，跑 largetest、WikiFact、MMLU，并额外跑 Mistral mechanism probe。 |
| 论文主表打印 | `scripts/print_aaai_table_v2.py` | 从已有 `outputs/eval_*_v2.json`、WikiFact、BoolQ PMI、MMLU JSON 读取摘要并打印表格。 |
| 旧版结果表 | `scripts/print_final_table.py` | 仍保留旧 largetest / WikiFact 摘要入口，不应优先作为当前 clean/audited 主表来源。 |

当前口径边界：

- `scripts/eval_new_models.sh` 和 `scripts/eval_mistral_e4.sh` 仍使用 `data/processed/splits/large_test/test.jsonl`，不是当前论文主表强调的 397 条 label-audited E4 v2 / clean strict 子集。
- E4 候选排名里 MGNM 主结果依赖 oracle behavior token，脚本用 `--neg-prefix auto`；不能和 no-token 或 router 设置混为同一主表行。
- WikiFact 是 suppress-only 域外评测，脚本用固定 `--neg-prefix "[SUPPRESS]"`；这不是自动 router 口径。
- MMLU 使用 `scripts/evaluate_mmlu.py --n-per-subject 10 --seed 42`，应写作 570-question diagnostic subset，不应写成 full MMLU。
- BoolQ 主表由 `scripts/print_aaai_table_v2.py` 读取 raw / PMI 文件；Llama raw 退化应继续写成 calibration + retention tradeoff，不应写成单纯校准已解决。

研究判断：

- 该梳理服务 RQ2 / RQ3：确认跨架构主结果复现入口存在，但当前入口和论文主表 audited split 之间仍需要显式映射。
- Mistral 现有证据可支持 cross-architecture sanity check；由于 Mistral baseline 仍不如 Qwen/Llama 完整，若未补齐 DPO / NC-SFT，不应把它写成三架构全 baseline 闭环。
- Qwen/Llama 主结果进入论文主表前，应优先使用 audited E4 v2 / clean strict JSON 汇总；旧 `large_test` 结果只能作为历史或诊断记录。

## 是否进入论文

本日志本身不进入论文结果表；它可作为 reproducibility appendix 或内部复现说明的来源。

可进入论文的仍应是已有 JSON/CSV/表格产物，并且需要满足：

1. 固定 audited E4 v2 / clean strict split；
2. 同时报告 Hard NegRank、Multi-answer NegRank、NegFlipAcc、ScopeCtrl、OverNeg、NegSuppRate；
3. Qwen / Llama 有对应 baseline、WikiFact、BoolQ raw/PMI、MMLU diagnostic；
4. Mistral 明确标注为 partial cross-architecture validation，除非补齐同口径 baseline。

## 风险和下一步

风险：

- 当前跨模型 shell 入口仍以 `large_test/test.jsonl` 为默认输入，直接用于论文主表会造成 split drift。
- `configs/model_config.json` 含本地绝对模型路径；这符合当前机器复现，但 release 前需要提供 example config 或 CLI 覆盖方式。
- `outputs/` 中的历史 JSON 命名同时包含 v2、largetest、clean strict、WikiFact、BoolQ、MMLU，后续聚合脚本必须显式列出每行 source，避免拿错文件。
- 本轮未运行重模型评测；没有新增结果，也不证明现有输出文件仍完整存在。

下一步建议：

1. 在已有 `eval_clean_strict.py` / `eval_wikifact.py` / `eval_boolq.py` / `eval_mmlu.py` 标准入口合并后，写一个 row-spec 驱动的主表复现清单，逐行绑定 source JSON。
2. 若继续推进 Mistral，优先补 Mistral NC-SFT 或 DPO 的同口径 audited E4 + WikiFact + MMLU diagnostic，而不是只新增 MGNM 变体。
3. 对 Qwen/Llama/Mistral 主表统一保留 `--neg-prefix auto`、router/no-token、WikiFact `[SUPPRESS]` 三类设置的显式标签，防止 token 口径混用。
