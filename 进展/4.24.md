## 主要工作

**上午（问题诊断）**

对 R3v4 结果做深度 per-behavior / per-scope 拆分，定位三类遗留问题的根因：

| 问题 | 根因 |
|---|---|
| OverNegRate=18.6% | 训练数据 scope 严重失衡（in_scope:out:double=52:30:18），out_of_scope 和 double_neg 见得太少；λ_preserve=1.0 不足以补偿 |
| NegRankAcc=50% | select_gold_neg 无 behavior token，L_rank 信号与其他损失等权竞争；epoch 3 L_rank=0.192 ≈ L_preserve=0.195，无优先级 |
| Llama ScopeCtrl=62.3% | 同 OverNeg 根因，Llama 更激进（NegSuppRate=100%）导致更严重的 scope 越界 |
| Phase 2 失败 | select_gold_neg 训练强化"偏好 neg"行为，直接冲突 preserve_positive 目标；ScopeCtrl −8.9pp |
| R3v4 eval loss 过拟合 | weight_decay=0.0，412条×3epoch 的小数据集导致 epoch 2 eval loss 跳至 2.79（train=0.32） |

关键发现：OverNeg 失败**只出现在 out_of_scope（20.9%）和 double_negation（13.5%）**，in_scope 完全正确（0%）——直接反映 3:1:1 scope 权重造成的学习不均衡。

**上午（代码修改 + 实验设计）**

在 `train_mgnm.py` 中新增 `--scope-oversample N` 参数：对 `out_of_scope` 和 `double_negation` 记录在训练前复制 N-1 份，从数据层面补偿 scope 失衡，无需重新生成数据。

R3v5 设计（三项并发修复）：

| 参数 | R3v4 | R3v5 | 针对问题 |
|---|---|---|---|
| λ_preserve | 1.0 | **2.0** | OverNegation |
| λ_rank | 1.0 | **1.5** | NegRankAcc（1.5 非 2.0，避免 Phase 2 覆辙） |
| weight_decay | 0.0 | **0.01** | eval loss 过拟合 |
| scope_oversample | 1 | **2** | out_of_scope/double_neg 各增一倍 |
| 有效训练条数 | 412 | **609** | — |

**上午（R3v5 训练，GPU 4）**

训练 3 epoch，eval loss 曲线正常：1.37→1.24→1.29（R3v4 对比：1.77→**2.79**→2.03）。无过拟合跳升，weight_decay 有效。

**上午（R3v5 三项评测并发，GPU 5/6/7）**

large_test、WikiFact、MMLU 同时启动。

## 关键结论

1. **R3v5 是目前 large_test 综合最优模型**：NegRankAcc 从 50% 提升到 56.9%（仍落后 Vanilla SFT 7pp），ScopeCtrl 从 81.4% 升至 86.8%（接近零提示基线 86.2%），OverNeg 降至 13.2%
2. **scope_oversample=2 对 out_of_scope 有效，对 double_negation 无效**：double_neg 的 13.5% OverNeg 需要专项分析
3. **MMLU 损耗 −3.33% 是主要负面**：过多有效训练量导致遗忘；若需兼顾 MMLU，可考虑 scope_oversample=1（只靠 λ 调整）
4. **WikiFact 评测需修复**：`forbidden_neg=[]` 导致 suppress_target 记录无法正确计算 NegSuppRate

## 下午（问题根因 Fix）

**Fix 1：WikiFact 评测 bug（evaluation.py）**

原因：`suppress_target` 记录 `forbidden_neg=[]` 时，`neg_suppressed` 计算中 `forbidden_scores=[]` → 恒 False。修复方案：`forbidden_neg` 为空时 fallback 到 `gold_pos` 作为 forbidden 集（语义正确：WikiFact 中 gold_pos = 应被抑制的概念）。同步将 `gold_pos` 加入 neg_candidates，使模型可以对它评分。

重评结果：
| 模型 | NegSuppRate | FlipAcc |
|---|---|---|
| R3v4（修复后） | 92.0% | 84.0% |
| **R3v5（修复后）** | **94.0%** | **88.0%** |

**Fix 2：`--dn-oversample` 参数（train_mgnm.py）**

将 `--scope-oversample` 拆分为 out_of_scope 和 double_negation 各自独立的倍率，支持 `--dn-oversample N` 单独控制 double_neg 的重采样。

**Fix 3：MMLU 对照实验 R3v5_noOS（GPU 1）**

去掉 scope_oversample，仅保留 λ 调整：λ_preserve=2.0, λ_rank=1.5, weight_decay=0.01，412条×3epoch。

**Fix 4：double_negation 专项实验 R3v6（GPU 4）**

scope_oversample=2 + dn_oversample=4，总 757 条训练记录。

## 关键发现

1. **R3v5_noOS 是当前最优模型**：λ 调整（λ_preserve=2.0, λ_rank=1.5）+ weight_decay=0.01 本身足以解决全部问题，无需 scope_oversample
2. **scope_oversample 有害无益**：R3v5（OS=2）比 R3v5_noOS 各项指标均差，且 MMLU 损耗更大（−3.33% vs −2.81%）。原因：额外的 197 条训练记录（77步/epoch vs 52步/epoch）带来更多梯度更新，反而干扰收敛
3. **double_negation 自然被 λ_preserve=2.0 解决**：R3v5_noOS 的 dn OverNeg 仅 1.9%（R3v4 为 13.5%），无需专项处理
4. **R3v6（dn×4）失败**：dn 重采样 4x 引入过多 preserve_positive 梯度，导致 NegSuppRate 跌至 93.8%、NegRankAcc 崩至 31.2%。过度倾斜 preserve_positive 使模型不敢抑制
5. **WikiFact OOD 确认**：R3v5_noOS 下 WikiFact（修复后评测）待补充；已知评测代码修复有效
