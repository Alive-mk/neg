## 关键结果

### 1. GPU 未被使用的原因

默认 Codex sandbox 中：

```text
torch 2.9.0+cu128
cuda runtime 12.8
cuda init error: RuntimeError No CUDA GPUs are available
is_available False
count 0
```

同一命令用非 sandbox 权限运行：

```text
torch 2.9.0+cu128
cuda runtime 12.8
cuda init ok
is_available True
count 8
```

因此 GPU 空闲的直接原因是默认 sandbox 隔离了 PyTorch CUDA 初始化。后续真实 GPU 评测需要用已授权的 `python scripts/eval_clean_strict.py ...` 路径运行。

### 2. Clean strict no-token 真实评测

数据：`data/processed/validated_largetest_v2_clean_strict.jsonl`

模型：`qwen2_5_7b`

口径：`--token-mode no-token`

样本数：397

结果：

```text
PosAcc: 72.80
NegSuppRate: 42.27
NegRankAcc: 39.60
MultiAnswerNegRankAcc: 39.60
FlipAcc: 17.73
ScopeControlAcc: 87.76
OverNegationRate: 12.24
```

GPU 运行时观察到 GPU0 约 14.9GB 显存占用、约 90% 利用率。

### 3. Clean strict oracle-token 真实评测

数据：`data/processed/validated_largetest_v2_clean_strict.jsonl`

模型：`qwen2_5_7b`

口径：`--token-mode oracle`，即 `--neg-prefix auto`，使用 `expected_neg_behavior` 注入 oracle behavior token。该口径不是自动 router。

样本数：397

结果：

```text
PosAcc: 72.80
NegSuppRate: 43.30
NegRankAcc: 36.63
MultiAnswerNegRankAcc: 36.63
FlipAcc: 17.39
ScopeControlAcc: 86.73
OverNegationRate: 13.27
```

相对 no-token，当前 base Qwen2.5-7B 的 oracle token 并未带来整体提升：NegSuppRate 小幅上升，但 NegRank、FlipAcc、ScopeControlAcc 下降，OverNegationRate 上升。这符合“base 模型不能直接解释行为 token”的预期，不能当作 MGNM oracle 结果。

### 4. Leakage checker 发现真实数据风险

`merged_excl_boost/train_clean_strict` vs `validated_largetest_v2_clean_strict`：

```text
ok: false
failed_overlaps:
- entity_id: 2
- family_id: 1
- template_id: 3
```

`e4v3_unseen_template_multianswer` release：

```text

- dev/test source_record_id: 1
- dev/train holdout_group: 58
- dev/train source_record_id: 1
- test/train source_record_id: 17
```

这些结果说明当前相关 split 不能直接宣称严格 entity/family/template/source-record holdout，需要重新定义主表使用的 split 或在论文中明确限制。

## 今日目标

P0-A / RQ3：基于 2026-05-21 的 leakage 报告，重建一个可宣称 strict holdout 的 clean strict / E4v3 multi-answer release split。目标不是提升模型分数，而是让后续 clean strict、router、WikiFact 对照不建立在泄漏 split 上。

## 修改文件

- `scripts/build_strict_holdout_split.py`：新增 connected-component holdout splitter，把共享 `prompt_pair/template_id/family_id/entity_id/source_record_id` 的样本归入同一 component，再按 component 切分。
- `scripts/check_leakage.py`：`source_record_id` 增加读取 `metadata.source_metadata.source_id`，避免 E4v3 release 嵌套 source id 被漏检。
- `进展/2026-05-21.md`：记录本轮真实数据实验闭环。
