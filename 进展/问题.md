### P2. Llama BoolQ raw 退化

#### 当前结果

| 模型 / 设置 | BoolQ raw | 标准 PMI α=1 | Held-out scalar PMI |
|-------------|----------:|-------------:|--------------------:|
| Llama Base | 83.2 | -- | -- |
| Llama MGNM | 69.0 | 81.4 | 85.0 |
| Llama ret01（λ_ret=0.1） | 83.3 | 待补 | 待补 |
| Llama ret02（λ_ret=0.2） | 84.8 | 待补 | 待补 |
| Llama tradeoff（lr=1e-4, λ_sup=0.7, λ_ret=0.2） | 84.1 | 待补 | 待补 |

正式 seed=7 calibration/test split：

| 模型 / 设置 | Calibration alpha | Held-out raw | Held-out PMI α=1 | Held-out tuned |
|-------------|------------------:|-------------:|-----------------:|---------------:|
| Llama Base | 0.00 | 83.33 | 74.81 | 83.33 |
| Llama MGNM | 1.74 | 69.11 | 81.54 | 85.02 |

#### 根因

1. MGNM 的 $\mathcal{L}_\text{sup}$ 引入更强 null-context No prior。
2. Llama Base 原本有 Yes 偏置，MGNM 把先验翻到 No 之后，raw yes/no QA 明显退化。
3. 标准 PMI α=1 校正不足；scalar α 需要到 1.65-1.88 区间。

#### 已解决部分

校准层面已经足够防守：

- repeated held-out：`84.63% ± 0.31%`
- seed=7 单一 split：`85.02%`
- 说明问题主要是校准偏移，不是不可恢复能力损伤。

#### 仍未解决部分

Raw 退化已被现有 retention checkpoint 证明可以修复，但还不能直接替换主模型：

- `ret01` BoolQ raw = 83.3%，但 E4 为 NegFlipAcc 57.3 / ScopeCtrl 94.0 / NegRank 45.8，SELECT 明显弱于当前主线。
- `ret02` BoolQ raw = 84.8%，但 E4 select 更差（旧 full392 上 NegRank 31.2）。
- `tradeoff_sup07_ret02_lr1e4` BoolQ raw = 84.1%，但 E4 退化为 NegFlipAcc 46.2 / ScopeCtrl 64.3 / NegRank 46.5，WikiFact 也只有 54.0。
- 因此论文主模型继续保留当前 E4 最强/均衡 checkpoint，把 BoolQ raw 问题写成 calibration + retention tradeoff。

若要继续修到“raw 高且 E4 不掉”，需要新重训：

1. Llama learning rate 从 `2e-4` 降到 `1e-4` 或 `5e-5`。
2. $\lambda_\text{sup}$ 从 `1.0` 降到 `0.5 / 0.7`。
3. $\lambda_\text{ret}$ 从 `0.10` 提到 `0.2 / 0.3`。
4. 加少量 BoolQ-style retention data。

状态：**raw 可由 retention / 降 sup 重训修复，但会牺牲 E4 NegRank 或 ScopeCtrl；当前未获得同时保留 E4 与 BoolQ raw 的最终 checkpoint。**

2026-05-09 更新：折中重训 `outputs/llama_tradeoff_sup07_ret02_lr1e4` 已完成，配置为 `lr=1e-4, λ_sup=0.7, λ_ret=0.2, λ_rank=1.5, λ_preserve=1.5`。结果显示它能把 BoolQ raw 拉到 `84.1%`，但 E4 strict 只有 `46.2 / 64.3 / 46.5`（NegFlipAcc / ScopeCtrl / NegRank），WikiFact 只有 `54.0%`。该 checkpoint 不采用；它强化了“BoolQ raw 与 E4 条件控制存在训练权衡”的结论。

### P3. Auto-router 泛化验证

#### 当前结果

| 设置 | NegFlipAcc | ScopeCtrl | NegRank | NegSupp | OverNeg |
|------|-----------:|----------:|--------:|--------:|--------:|
| Candidate LLM + empty SELECT | 59.5 | 69.4 | 61.4 | 89.7 | 30.6 |
| Two-stage supervised router | 61.9 | 87.8 | 60.4 | 100.0 | 12.2 |
| Two-stage supervised router + empty SELECT | 61.9 | 88.8 | 61.4 | 96.9 | 11.2 |
| Two-stage + suppression-only guard + empty SELECT | 62.9 | 88.8 | 61.4 | 100.0 | 11.2 |
| Oracle token | 64.2 | 92.9 | 63.9 | 100.0 | 7.1 |

Label-level strict：

| 设置 | 行为准确率 | suppress acc | preserve acc | select acc |
|------|-----------:|-------------:|-------------:|-----------:|
| Two-stage router | 92.9 | 94.8 | 93.9 | 91.6 |
| Two-stage + suppression-only guard（t=0.35） | 94.2 | 100.0 | 93.9 | 91.6 |

Family-heldout calibration 诊断：

| 口径 | 行为准确率 | suppress acc | preserve acc | select acc | 下游 NegFlipAcc | ScopeCtrl | NegRank |
|------|-----------:|-------------:|-------------:|-----------:|----------------:|----------:|--------:|
| train-fit vs calibration family-heldout | 66.7 | 33.3 | 78.9 | 70.5 | 71.4 | 100.0 | 72.7 |

WikiFact 域外 router 诊断（100 条，全部 `suppress_target`）：

| 设置 | 行为准确率 / suppress recall | 下游 NegFlipAcc | 说明 |
|------|-----------------------------:|----------------:|------|
| Two-stage router + empty SELECT | 29.0 | 78.0 | 71/100 被误判为 SELECT；低于 oracle Qwen MGNM 91.0 |
| Two-stage + suppression-only guard | 100.0 | 91.0 | 使用 `semantic_mode=suppression_only` 元数据，恢复到 oracle token 水平 |

#### 根因

旧 router 的问题不是总准确率，而是 preserve 被吸进 SELECT。Two-stage preserve-first router 直接修复 preserve recall，因此 ScopeCtrl 从 69.4 到 88.8。

#### 当前边界

1. E4 内自动路由已接近 oracle，不再是最大短板。
2. train-fit / calibration 的 family overlap 为 0，但 calibration 仍来自 E4 分布，且样本只有 75 条。
3. WikiFact 域外诊断显示纯 two-stage router suppress recall 只有 29.0%；加入 `semantic_mode=suppression_only` guard 后可恢复到 100.0% suppress recall / 91.0% downstream。
4. 该修复依赖 benchmark 元数据，不能宣称纯文本通用自动路由已解决。

#### 下一步

最小验证：

1. 在 family-heldout calibration/test split 上重训/选阈值再测 strict。
2. 若要去掉元数据依赖，需要针对 WikiFact / suppress-only 域外样本训练纯文本 suppress-first 分支或独立域外 calibration。
3. 小规模 free-gen suppress/preserve 上测 router 是否选对 token。

状态：**已用 suppression-only guard 修复 WikiFact 域外失败；剩余限制是该 router 依赖结构化元数据，不是纯文本通用 router。**

> 如果行为 token 是方法核心，为什么开放生成 preserve 反而不能用？

## 5. Mistral 仍然只有 Base vs MGNM，没有 NC-SFT / DPO

这个结果本身不难看，反而不错。问题是**对比不完整**。Mistral 没有 DPO / NC-SFT / Vanilla SFT，所以只能支持 “architecture sanity check”，不能强力证明 MGNM 在 Mistral 上也优于微调基线。
