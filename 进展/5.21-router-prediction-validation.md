# 2026-05-21 Router 预测覆盖校验

## 今日目标

原因：`eval_with_router.py` 以前对缺失的 `record_id` 使用空字符串前缀，导致不完整 router 预测文件会被静默当成 no-token / empty-prefix policy。这样会污染 RQ4 的 downstream NegFlipAcc、ScopeCtrl 和 NegRank 结论，尤其无法区分“模型策略选择空前缀”和“预测文件漏了样本”。

## 修改文件

- `scripts/eval_with_router.py`

## 运行命令

```bash
python -m py_compile scripts/eval_with_router.py
python scripts/eval_with_router.py --help
python - <<'PY'
from types import SimpleNamespace
from scripts.eval_with_router import validate_predictions

records = [SimpleNamespace(id="keep-1"), SimpleNamespace(id="keep-2")]

try:
    validate_predictions({"keep-1": "[SUPPRESS]"}, records)
except SystemExit as exc:
    print("missing-check:", str(exc))
else:
    raise SystemExit("missing-check did not fail")

try:
    validate_predictions({"keep-1": "[BAD]", "keep-2": "[PRESERVE]"}, records)
except SystemExit as exc:
    print("invalid-token-check:", str(exc))
else:
    raise SystemExit("invalid-token-check did not fail")

validate_predictions({"keep-1": "[SUPPRESS]"}, records, allow_missing_as_empty=True)
validate_predictions({"keep-1": "", "keep-2": "[SELECT]"}, records)
print("allow-and-complete-check: ok")
PY
```

## 关键结果

- 新增 `validate_predictions()`：
  - `--predictions` 必须是 JSON object；
  - token 只能是 `""`、`[SUPPRESS]`、`[SELECT]`、`[PRESERVE]`；
  - 默认要求每条 input record 都有预测；
  - 只有显式传 `--allow-missing-as-empty` 时，才把缺失 id 当空前缀。
- 这不改变 router token、prompt、candidate pool 或任何 metric 公式，只把原来的隐式空前缀 fallback 改成显式选择。

## 风险和下一步

- 风险：历史脚本若依赖“预测缺失即 no-token”的隐式行为，现在需要补全预测文件，或显式加 `--allow-missing-as-empty`。
- 下一步：若后续补统一 `scripts/eval_router.py`，应复用同一覆盖校验，并把 no-token / empty-SELECT policy 的预测文件生成步骤写清楚。
